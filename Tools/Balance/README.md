# Read-only balance laboratory, version 0

The checked-in results.json.gz archive contains the complete generated JSON; plain
results.json is regenerated locally and excluded from git. The --all-teams run
evaluates all 210 distinct four-hero teams against three disclosed reference
opponents (630 matches), not an all-versus-all tournament. All 180 basic scenarios
also run at half the default 0.00625-second timestep. Numerical outcome changes
and score differences are reported rather than hidden.

Run from any directory with Python 3.10+ and no third-party dependencies:

```
python Tools/Balance/balance.py --all-teams
cd Tools/Balance && python -m unittest -v
```

The tool reads current C# catalogs, never changes gameplay and writes only its own `output` directory. `--output PATH` chooses another output location. Source SHA256 hashes are recorded in results.json. No git commit is assumed: hashes identify the actual inputs, including local changes.

Primary output is a **basic-engagement index**, no abilities/passives. It measures equal-weight deterministic 1-D scenarios, NOT hero balance or human win probability. Aggregate index average is 100 by pair complement, rather than a chosen damage/control weighting. Source Brakk +5% outgoing damage still applies. Supported-passive and asymmetrically incomplete kit runs are separate sensitivity experiments. Do not compare kit indices as whole-hero strength. No automatic balance changes.

`results.json` includes all per-match damage, absorbed shield, healing received, healing generated by allies, HP versus HP+shield lost before first successful hit, time to first hit, range uptime, matchup indices, source values, scenario scores and controlled team swaps. Role-relevant axes remain separate; no arbitrary weighted 'support versus assassin' score is invented. Team utility is the result relative to other candidate heroes inserted into the same core. Experimental swaps use fixed candidate cores; the separate --all-teams baseline covers all 210 compositions against three reference opponents. Opposing teams may share heroes; a team may not contain duplicates.

Read output/report.md for exact omissions. Major limits include 1-D unbounded space, instant dash distance, incomplete kits/CC, ideal aim, and no objectives/network. A plausible next step is porting one ability at a time, matching actual Unity regression outcomes, then adding 2-D engagement and live-match calibration. Only then should complete role-aware hero scores be produced.
